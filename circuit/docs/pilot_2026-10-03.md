# Circuit pilot, 2026-10-03: 5 bugs × 5 modes

**Setup.** Bug numbers 1-5. Bug types rotate with the bug number, so the pilot has two swapped muxes, one wrong
forwarding priority, one off-by-one comparator and one stuck-at bit. Every mode had the same limits: 40 probes and
$0.40 per case, with a 4-cycle check window. The swarm used 8 Irregulars, 2 probes each per round, at most 10 rounds,
mixed assignments (some got one block, some a window of the waveform). Jev is `typesafe/jev-1.13` through OpenRouter;
the genius is `gpt-6-astra` with up to 8 turns and 6 probes per turn. Raw rows: [`pilot_2026-10-03.csv`](pilot_2026-10-03.csv).
To reproduce: `cd circuit && PYTHONPATH=.:../common python3 -m cpudebug.batch --modes jev,hybrid,cone,rule_swarm,genius --seeds 1-5`.

## What the pilot shows

1. **The Jev swarm locates the bug, at about 1/45 of the genius's cost.** It found the faulty block and signal in
   5/5 cases. Each case took 20-58 Jev calls and about $0.001. It also used fewer probes than any exact baseline
   (16.8 on average). The Irregulars' "which input carried the bad value?" pointers send Wiggins' next round up the
   right branch of the back-slice.
2. **Jev's weak step is naming the fix, not finding the block.** On bug 3 the swarm caught `br_lt` misbehaving, but
   Jev Holmes chose "output bit 0 stuck at 0" instead of "computes A <= B". In the observed rows both faults change
   the same bit at the equality boundary. The exact fault fitter in the hybrid separates them with bench drives. This
   is the only Jev miss.
3. **The hybrid (Jev steers, exact logic judges) fixed 5/5 for $0.0014 a case.** It is the best result per dollar
   among the modes that use a model. It can spend more probes than the Jev swarm (40 on bugs 2 and 3) because exact
   verdicts never stop on a hunch.
4. **Serial cone tracing is cheap when the bug is close to the failure, and it runs out of probes when the bug is
   deep.** It took 5 probes on the ALU bug. On the forwarding-priority bug it was still working through the nearest
   layers of the back-slice (pipeline control, decoders) when the 40 probes ran out. It then guessed `dec_rs2`.
   Running the same exact rules as a parallel swarm (rule swarm) fixed 5/5. It spent more probes on easy bugs, but it
   reached deep branches sooner.
5. **The genius is the most accurate, but the comparison favours it.** gpt-6-astra solved every case in 2-3 turns
   with **one** probe, at $0.04-0.07 a case, well inside its $0.40 budget. Most of its edge comes from the free
   waveform reads. It reads the forwarding selects and operand nets directly, guesses the block from the pipeline
   timing, and spends its single probe confirming. The swarm's Irregulars see only their own block's ports. A fairer
   next comparison would either charge reads or give each Irregular a few reads too.

## Caveats

* Five bugs are an anecdote, not a benchmark. Bugs 1 and 5 are both forwarding-mux swaps. Run more seeds before
  quoting any rate.
* Exact "spec_out" values are shown to every investigator, so a check is a strong probe. Locating the block is
  mostly a search problem (where to probe within the budget), not a reading problem.
* With the probe budget at 40, cone tracing hits the cap on deep bugs. A budget of 20 would separate the swarm modes
  more; a budget of 80 would let cone tracing finish every case.
